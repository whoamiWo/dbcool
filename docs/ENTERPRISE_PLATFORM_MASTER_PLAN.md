## 一、执行摘要

### 总体判定：**核心业务闭环已成熟，缺口集中在"对外连接"与"商业化"**

现有平台已完成一个相当完整的企业协作底座：

| 已成熟能力 | 对标水平 |
|---|---|
| 数据模型引擎（Collection/字段/公式/汇总/关联） | Airtable / NocoDB 级 |
| 表单（含公开表单、分享、校验、显隐规则） | Airtable / NocoBase 级 |
| 视图（表格/看板/画廊/日历/详情/时间线） | Trello / Airtable 级 |
| 权限（记录级/操作级/角色继承/Schema 级租户隔离） | NocoBase 级 |
| 工作流（8 节点 + 死循环防护 + 版本/模板） | NocoBase 级 |
| IM（频道/私信/线程/表情/已读/在线/Huddle 音视频） | Slack / RocketChat 级 |
| Wiki（版本快照/对比/双向链接/锚文本/混合检索） | Notion 级 |
| 集成（钉钉/企微/飞书/Slack/Mattermost + 集成市场） | 覆盖面广 |

**但存在四个结构性短板**（决定"能否真正用于中国企业"）：

| # | 短板 | 影响 |
|---|---|---|
| 1 | **JS-SDK 签名全平台缺失** | 只能"扫码登录 + 发消息"，**无法把页面嵌入钉钉/企微工作台**、无法调原生能力（选人/拍照/分享） |
| 2 | **微信生态基本空白** | 无公众号 OAuth、无小程序登录、无 JS-SDK —— 国内最大流量入口未打通 |
| 3 | **外部数据源完全缺失** | 无法对接企业已有的 MySQL/PG/ERP，只能新建数据 |
| 4 | **计费/套餐/支付缺失** | 多租户与配额已就绪，但无法商业化变现 |

另有一项**静默风险**：K8s 环境 `CRDT_SERVICE_URL` 未配置 → 协同降级为整篇替换（后写覆盖先写），
而 Docker Compose 环境正常，**问题只在 K8s 暴露**，极易被忽略。

## 二、七产品对标结论

| 产品 | 核心优势 | 本平台覆盖 | 主要差距 |
|---|---|---|---|
| **Airtable** | 表格/视图/公式/关联 | ✅ 85% | 批量编辑前端入口、冻结列、条件格式、数组公式函数 |
| **NocoDB** | 外部数据源、开源自建 | ❌ 0%（数据源） | **外部数据源完全缺失**（最大差距） |
| **NocoBase** | 插件/工作流/权限 | ✅ 90% | 字段级权限、子工作流、延时节点 |
| **Slack** | 频道/线程/App 生态 | ✅ 85% | @全体提及、消息引用、App Directory |
| **RocketChat** | 音视频/多端 | ✅ 80% | 消息撤回窗口、会话管理 |
| **Trello** | 看板/Card/Checklist | 🟡 70% | **看板无拖拽**、甘特图缺失、Checklist 弱 |
| **Notion** | 块编辑/双向链接/数据库 | ✅ 95% | 块级权限、分享统计、模板库 |

## 七、实施原则

1. **实证优先** — 所有判定附代码位置/实测命令，禁止推断。
2. **复用现有设施** — 优先复用 `Collection` 引擎、`ExternalUserMapping`、`integration/credential/`、Redis 缓存，不建平行服务。
3. **配置三处核查** — 新增 `@Value` 注入须同时核查 `application.yml`、`docker-compose.yml`、`k8s/*.yaml`（CRDT 即为反面案例）。
4. **先解阻塞再追体验** — Phase A 四项性价比最高，优先推进。
5. **许可合规** — 保持与 NocoBase 代码独立（其 Apache-2.0 补充条款禁止 SaaS 化），不 fork。
