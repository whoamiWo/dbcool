## §3 验证方式（本批的成败关键 —— 移动端是假完成高发区）

**只加 CSS 不算完成。每条必须有移动端视口的真实验证。**

### T3 移动端视口测试（P0）

用 Playwright 在**真实移动设备尺寸**下断言：

```ts
test.use({ viewport: { width: 375, height: 812 } });   // iPhone X/13 逻辑分辨率
```

每个适配页面至少断言三项：

1. **无横向滚动**：`document.documentElement.scrollWidth <= clientWidth`
   （这是移动端最常见的坏体验，也是最容易蒙混过关的一项）
2. **关键元素可见且可点**：登录按钮 / 提交按钮 / 主导航项在视口内可见
3. **布局生效**：如侧边栏在移动端默认收起、点汉堡后展开

交付要附**移动端视口截图**（每个页面 1 张），不能用桌面截图冒充。

### 判定标准（写进验收）

| 检查 | 通过条件 |
|---|---|
| 横向滚动 | 375px 宽下 `scrollWidth <= clientWidth` |
| 触控目标 | 主要按钮 ≥ 44×44 px（iOS HIG 最小触摸区） |
| 功能不丢失 | 移动端可见的操作项 = 桌面版的核心操作项 |
| 截图 | 真实移动端视口截图，非桌面缩放 |

## §5 红线（违反即打回）

1. **严禁只加 CSS 不验证** —— 必须有移动端视口测试（本项目 UI 类交付翻车过多次）
2. **严禁横向滚动** —— 375px 下不得出现横向滚动条
3. **严禁因适配藏掉功能** —— 移动端不能因为放不下就把操作删掉，必须收进菜单/抽屉
4. **严禁引入 Tailwind** —— 与现有 `styles.css` 冲突，走原生媒体查询
5. **严禁伪造截图** —— 必须是真实移动端视口产物
6. 严禁修改已应用的迁移文件
